# ARTEX BaaRai 版（飞牛原生 fpk）

AI 驱动的自动化安全测试平台。本包为**飞牛原生打包**：内置 PostgreSQL 16.14 运行时，
安装后不依赖 Docker、不需要外部数据库、也不联网下载依赖。

## 安装后

- 访问 `http://<NAS-IP>:8787/` 完成首次初始化（`/setup`）
- 安装后飞牛桌面会出现「ARTEX BaaRai 版」图标，点击即打开 Web 界面（包版本 0.6.1 起）
- 默认端口 `8787`，安装向导可修改
- 数据库由依赖包 `artexpg` 提供，固定监听 `127.0.0.1:55432`，不对外暴露
- 账号、任务、证据存放在应用数据目录，升级与重启后保留
- 包版本 0.6.3 起，共享目录由 `config/resource` 自动创建并授权；任务产物存放在应用共享目录 `/vol4/@appshare/artex`，即「文件管理 → 应用文件 → artex」，可直接查看与删除；升级时自动从旧目录迁移

## 0.6.3 修复（应用文件 / 共享目录）

- 现象：升级或重装 0.6.2 后，文件管理 → 应用文件 里找不到 artex
- 原因：飞牛的共享目录必须在 fpk 的 `config/resource` 中声明（`data-share.shares`），应用中心才会在安装/升级时创建 `/vol4/@appshare/artex`、修改属主并建立 `/var/apps/artex/shares` 软链；此前只写在 manifest 的 `data-share` 字段，系统不识别
- 修复：新增 `config/resource` 声明（名称 `artex`，读写授权给 `artex` 用户）。升级后应用中心会自动创建并授权，已有数据不受影响
- 上游二进制仍为 BaaRai/ARTEX v0.6.0，未修改上游代码

## 0.6.2 修复与变更

- **agent 执行命令全部失败**：报 `exec: "bash": executable file not found in $PATH`。应用中心拉起的进程没有 PATH，包脚本现在显式补齐标准目录
- **任务文件位置**：改为应用共享目录，首次启动自动迁移旧数据，目录不可用时自动回落
- 上游二进制仍为 BaaRai/ARTEX v0.6.0，未修改上游代码

## 与官方部署的区别

- 官方提供 Docker / 二进制两种方式；本包把上游二进制与 PostgreSQL 都打进 fpk，由飞牛应用中心管理生命周期
- 数据库密码安装时随机生成，保存在 `/vol*/@appdata/artexpg/pgpass`（0644，仅本机进程可读）
- 卸载 ARTEX BaaRai 版时可选保留或删除数据库；删除后不可恢复
- 包内「一键更新」不适用，升级由飞牛应用中心负责
